## 它解决什么问题

Codex 左侧任务的自动标题，常常会变成长句、临时措辞或泛化名称。**会话整理**根据任务的真实目标和最终交付，生成适合侧边栏阅读的标题，同时保留用户确认环节。

它整理的是任务标题，不是项目内容：不会改项目名称、对话正文、项目归属、排序、置顶或归档状态。

## 快速使用

在 Codex 中显式调用内部 Skill 名称：

```text
@会话整理 整理“个人网站”项目
```

也可以指定范围和执行方式：

```text
@会话整理 整理这个文件夹，使用当前模型
@会话整理 整理全部任务，使用子 Agent
@会话整理 解释这个标题的判断依据
```

未指定子 Agent 时，默认使用当前对话模型。

## 标题规则

标题格式固定为：

```text
MMDD | 类型 | 主题
```

类型限定为：`功能`、`设计`、`修复`、`优化`、`发布`、`探索`、`文档`、`研究`。

主题遵循“对象 + 动作/结果”，例如：

```text
0810 | 文档 | AGENTS.md 中文化与语言规范
0812 | 文档 | ClayAI 深色配色参考包
0805 | 研究 | 个人网站工具链与内容定位
```

日期优先使用任务的 `createdAt`，转换为 `Asia/Shanghai` 后取四位月日；没有 `createdAt` 时才使用 `updatedAt`。

## 证据优先，而不是标题猜测

每条候选标题都按以下顺序判断：

```text
用户真实目标 → 对话最终交付结果 → 项目上下文
```

Skill 会区分“项目主题”和“任务主题”，并在内部保留任务 ID、时间来源、用户目标、最终结果、类型理由、主题理由和置信度。

如果对话主线冲突、上下文不足或只能根据旧标题猜测，就保留原名称，不强行改名。用户追问时，可以按任务解释标题依据。

## 先预览，再修改

整理分为两个阶段：

1. 读取范围和必要上下文，只输出严格的两列表格：

   ```text
   | 原名称 | 新名称 |
   ```

2. 用户明确确认后，才按任务 ID 调用标题更新能力。

预览阶段不会修改任何任务。确认后也只修改标题，不执行删除、归档、置顶、移动、排序或项目变更。

## 四种整理范围

| 范围 | 匹配方式 |
| --- | --- |
| 单个任务 | 任务 ID，或先定位后确认具体任务 |
| 项目 | 项目 ID 或项目名称 |
| 工作区 / 文件夹 | 任务 `cwd`，包含目录本身及子目录 |
| 全部任务 | 当前宿主可访问的任务，合并置顶与普通列表并去重 |

默认不扩大用户指定的范围。

## 可选的子 Agent 流程

子 Agent 是通用的可选执行通道，不绑定某台电脑上的 Provider、模型 ID、插件或 Agent 角色。

- 未指定时：当前对话模型完成全部流程。
- 指定子 Agent 或 PA 模型时：由宿主环境提供并解析实际模型配置。
- 只说“便宜模型”时：由宿主选择适合短文本整理的低成本配置。
- 子 Agent 只负责读取、提炼证据和生成候选标题。
- 主对话负责范围确认、结果审查、用户确认和最终改名。
- 指定的子 Agent 不可用时，不静默切回当前模型；除非用户允许回退，否则保持标题不变。

为了控制上下文成本，不默认复制完整会话历史。读取顺序是：任务元数据 → 主要用户请求与最终结果 → 发生冲突时再读取更早历史。

## 宿主要求

Skill 需要运行环境提供任务和项目管理能力，用于：

- 发现项目、路径、标题和时间；
- 读取任务的实际对话内容；
- 在用户确认后按任务 ID 更新标题；
- （可选）提供通用子 Agent 委托接口。

本仓库不包含任何本机凭据、账号配置、项目路径或固定 Provider 设置。

## 安装

将此目录放入目标 Codex 环境的 skills 目录，并保留目录名 `session-title-organizer`。宿主会通过 `agents/openai.yaml` 显示中文名称“会话整理”，英文目录名作为稳定的内部标识。

## 限制

- Skill 不能访问宿主未公开的任务或对话。
- 标题质量依赖宿主提供的对话读取结果；上下文不足时会选择保留原名。
- 子 Agent 能否使用、可用模型和具体成本由宿主环境决定。
- GitHub 的 Skill 加载器是否支持中文显示名，取决于其是否读取 `agents/openai.yaml`；内部名称始终是 `session-title-organizer`。
